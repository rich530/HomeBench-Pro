### Global conventions
- Every business table: `id uuid pk default gen_random_uuid()`, `org_id uuid not null`, `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()` (trigger `set_updated_at`), `created_by uuid null references profiles(id)`, and a `unique (id, org_id)` so children can use **composite foreign keys** `(parent_id, org_id) references parent(id, org_id)`. This makes cross-org references impossible at the database level, not just by policy (AD-004).
- Soft delete via `archived_at timestamptz` on CRM tables; hard delete only by owner/admin.
- Money and quantity columns: `numeric(14,4)`. Percentages stored as fractions `numeric(14,4)` (0.4000 = 40%). No float columns anywhere.
- **Money segregation (CLAUDE.md 5.4):** any column holding cost, price, margin, charge, fee, or insurance dollars lives in a `*_financials` table keyed 1:1 to its parent. Enforced by the `money-columns` test (section 9). Reads that need both use `security_invoker` views named `*_with_financials`.
- `external_source text`, `external_id text`, `unique (org_id, external_source, external_id)` on accounts, sites, contacts, jobs (idempotent JobNimbus import in M4).
- All RLS policies call helpers with `(select auth.uid())` wrapping to keep them planner-cached; every `org_id` and FK column is indexed.

## 3. RLS helper functions and permission matrix

All helpers: `language sql stable security definer set search_path = ''`, owned by `postgres`, `revoke all ... from public`, `grant execute to authenticated`.

## 4. Audit design
- **App layer (primary):** `src/lib/audit.ts` exports `withAudit(ctx, meta, fn)`. Every server action that mutates data calls it: it runs `fn` (the mutation), then `rpc('log_audit', {org_id, action, table_name, row_id, before, after, reason})`. `log_audit` is security definer, sets `actor = auth.uid()`, `source = 'app'`, and rejects callers that are not members of `org_id`. A test lists every exported server action (files named `actions.ts` under `src/app`) and fails if it does not reference `withAudit` (T-005 creates the test; it passes vacuously until actions exist).
- **DB layer (backstop):** `audit_row()` trigger (`after insert or update or delete`, row level) writes `source='trigger'`, before/after as jsonb (minus `updated_at`), actor from `auth.uid()` (null for service role), reason from `current_setting('app.audit_reason', true)`. Attached in M0 to: organizations, org_settings, org_settings_financials, margin_targets_financials, memberships, invitations, jobs, job_financials, job_access, callbacks, callback_financials, and every later `*_financials`, price, rate, time, approval table.
- **Immutability:** `audit_log` has no update/delete policy and a `before update or delete` trigger that raises; truncate revoked from `authenticated`.
- **PII:** `before`/`after` are stored in the database only (allowed); nothing is written to application logs (CLAUDE.md 5.12). Server logs record ids, never names/phones/emails.

## 5. Engine and integrations

### 5.1 `src/engine` (pattern set now; M1 fills it)
- README: pure functions only, no I/O, no `Date.now()`, decimal.js everywhere, inputs `Decimal.Value`, outputs `EngineResult<T> = { value: T; trace: TraceStep[] }`, errors are `EngineError` with a code. Rounding points documented per function. 95% coverage gate (`coverage:engine`, enforced in CI from T-003).
- `priceFromMargin(cost, targetGm)`: `price = cost / (1 - targetGm)`, value rounded to 4 dp (storage precision, ROUND_HALF_UP); `toCents()` helper rounds to 2 dp ROUND_HALF_UP (the documented display/billing rounding point). Throws `EngineError('GM_OUT_OF_RANGE')` unless `0 <= targetGm < 1`; `EngineError('NEGATIVE_COST')` if cost < 0.
- `markupFromMargin(gm)`: `gm / (1 - gm)`, same guards.

### 9.3 How db tests impersonate users
`tests/db/helpers/impersonate.ts` opens a `pg` connection to local Postgres and runs each case in a transaction: `set local role authenticated; select set_config('request.jwt.claims', '{"sub":"<user>","role":"authenticated","email":"…"}', true);` then the statement; rollback. `fixtures/every-table.ts` inserts one row per table for org A (Committed) and org B (Lakeside) via the service role; a table present in `pg_tables` but missing from the fixture map fails the coverage test, so new tables cannot dodge RLS testing. Tenant-key overrides: `organizations → id`, `job_access → owner_org_id` (plus grantee checks in job-access.test), `profiles → shares_org`, reference tables `metros, zip_codes` (asserted read-only instead).
